Glossary

These terms have the same meaning in the user guides and backend lessons. The backend's domain glossary records the canonical resource vocabulary.

Resources and access​

TermMeaning
User accountYour login identity and personal credentials.
WorkspaceThe owner of operational resources, settings, capacity, and subscription.
MembershipYour access to one workspace, with a workspace role.
Workspace roleOwner, admin, operator, or viewer. Controls actions in that workspace.
Instance administratorA global account role for installation settings. It does not grant membership in every workspace.
InvitationAn offer to an existing account to join a workspace. It grants access only after acceptance.
CapacityThe workspace's allowed active managed-proxy count. Paused and archived entries stay stored without using active capacity.

Proxies and checks​

TermMeaning
HostA DNS hostname, IPv4 address, or IPv6 address where a proxy can be reached. Compatibility API fields may call this ip.
Proxy routeHost, port, and one exact credential pair. Shared route identity is independent of workspace management.
Managed proxyA workspace's management of a route, including its encrypted credential copy, lifecycle, failure state, and tags.
LifecycleActive, paused, or archived state of a managed proxy. Separate from health.
TagA workspace-owned name and color assigned to managed proxies. Tags can also match checker rules.
Checker profileEnabled proxy protocols and shared transport, timeout, and retries in Default or an Add/Replace tag rule.
Effective checker settingsThe result of combining workspace defaults and matching tag rules in priority order.
Proxy protocolThe proxy behavior used for a check or upstream connection: HTTP, HTTPS, SOCKS4, or SOCKS5.
TransportHow bytes travel. Magpie supports TCP, QUIC, and HTTP/3 in specified checker/listener combinations; SOCKS requires TCP.
JudgeA test URL reached through a proxy, with a workspace validation rule for its response.
Check cycleOne scheduled route visit by a worker. It can contain several protocol/judge assignments and request retries.
Check evidenceA result's verdict and configuration identity for a participating workspace.
Current healthThis workspace's health assessment using evidence matching its current effective settings.
Unknown healthNo applicable evidence, or a pending settings refresh. It does not prove failure.
Failure streakConsecutive eligible cycles with no success for one managed proxy, up to 255. A successful cycle resets it.
ReputationA score or label derived from check and enrichment evidence. It is separate from current health.

Discovery and traffic​

TermMeaning
Scrape sourceA webpage URL from which Magpie extracts proxy routes.
Source subscriptionA workspace's use of a source, including its fetch mode and settings.
Source tagging ruleTags to add to accepted proxies found in future scrapes. Existing assignments remain until removed.
Rotating proxy or rotatorA named workspace listener that selects upstream routes according to a policy.
ListenerThe host, port, protocol, and transport to which a proxy client connects.
UpstreamThe selected proxy through which Magpie forwards client traffic.
Rotator poolRoutes governed by one rotator's policy. The usable pool contains routes currently eligible for selection.
CONNECT tunnelA connection through an HTTP proxy that forwards bytes to a target, commonly for HTTPS. An established tunnel keeps its upstream.
Alert ruleA workspace-owned threshold condition with optional delivery destinations.
IncidentA sustained breach tracked until sustained recovery or a configuration change closes it.
Checker success rateThe proportion of attributed checker attempts that passed in an observation window. It does not measure your application's requests.

Backend concepts​

TermMeaning
WorkerA background routine that processes queued work. In Go, many run concurrently in one process.
QueueRuntime work waiting for its scheduled time, stored in Redis.
Sorted setA Redis collection whose numeric scores order entries. Magpie uses due times to schedule route checks.
ShardOne of several sorted sets used to distribute a large queue.
LeaseA temporary claim on a route. Expiry lets another worker recover interrupted work.
Fingerprint or route hashA stable keyed identifier derived from host, port, and exact credentials. Current queue payloads store it for reuse.
Runtime snapshotCompiled settings held in memory so workers can resolve checks without loading tags and configuration for every route.
Redis StreamA sequence of result entries that consumers can claim, process, acknowledge, and replay.
AcknowledgementRecording that a stream entry has been handled. Magpie acknowledges successfully handled results after persistence.
TransactionA database unit whose changes commit together or roll back together.
Idempotent ingestionReplaying an identified result does not create duplicate committed history or counters.
Read modelA derived table or cache shaped for reads, such as source totals or dashboard summaries.
Leader jobA job coordinated with a Redis lease so backend replicas avoid running the same maintenance concurrently.
OutboxDurable database rows awaiting external message delivery and retries.
